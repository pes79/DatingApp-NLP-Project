# 데이팅 앱 사용자 리뷰 감성 분류 및 이탈 요인 분석

> 국내 주요 데이팅 앱(틴더, 글램, 탄탄, 위피, 아만다) 리뷰 데이터를 기반으로,
> 사용자 불만의 실체를 데이터로 진단하고 건강한 소셜 플랫폼 설계를 위한
> 페인 포인트(Pain Point)를 도출한 감성 분류 파이프라인 프로젝트입니다.

---

## 1. 프로젝트 개요

### 1.1 배경 및 문제 정의
데이팅 앱 시장은 빠르게 성장하고 있으나, 이용자들의 이탈률 또한 매우 높은 산업군으로 알려져 있습니다. 흔히 이탈의 원인은 '매칭 실패'와 같은 서비스 본질적 한계로 여겨지지만, 본 프로젝트는 실제 사용자 리뷰 데이터를 정량적으로 분석한 결과 이탈의 핵심 원인이 이와는 다른 지점에 있다는 가설에서 출발했습니다.

### 1.2 프로젝트 목표
- 5개 주요 데이팅 앱의 실제 사용자 리뷰 52,500건을 수집하여 감성(긍정/부정/중립/관계없음)을 분류하는 파이프라인을 구축한다.
- 정량 분석을 통해 사용자 불만이 **'과도한 과금 유도'**, **'스캠(사기)/허위 계정 방치'**, **'시스템 오류'**에 집중되어 있음을 데이터로 검증한다.
- 도출된 인사이트를 바탕으로 플랫폼 신뢰도 개선을 위한 실무적 제언을 제시한다.

### 1.3 핵심 스토리라인
> "유저는 '매칭이 안 돼서' 떠나는 것이 아니라, '믿을 수 없어서' 떠난다."

단순 기능 불만이 아닌 **플랫폼 신뢰(Trust) 문제**가 이탈의 근본 원인이라는 점을 데이터 기반으로 규명하는 것이 본 프로젝트의 핵심 문제의식입니다.

## 2. 데이터셋 소개

| 항목 | 내용 |
|---|---|
| 수집 대상 | 틴더, 글램, 탄탄, 위피, 아만다 (Google Play Store) |
| 수집 방식 | 웹 크롤링 + 데이터 증강(Augmentation) 기법 병행 |
| 총 데이터 수 | 52,500건 |
| 라벨링 대상 | 샘플 2,000건 |
| 라벨 클래스 | 긍정 / 부정 / 중립 / 관계없음 (4-class) |
| 라벨링 방식 | 1차 AI 자동 라벨링 → 연구자 직접 검수(Human Validation) 완료 |
| 학습/평가 분할 | Train : Test = 8 : 2 |

리뷰 데이터는 앱스토어 특성상 텍스트 길이와 평점의 편차가 크고, 특정 시점(업데이트, 이벤트 등)에 리뷰가 집중되는 특징을 보였습니다. 이에 따라 전처리 및 EDA 단계에서 데이터 편향을 사전에 점검했습니다.

---

## 3. 분석 파이프라인

```
[1. 데이터 수집] → [2. 전처리] → [3. EDA] → [4. 라벨링] → [5. 모델링(KoELECTRA)] → [6. 인사이트 도출]
```

### 3.1 데이터 수집
Google Play Store의 앱별 리뷰를 크롤링하여 원천 데이터를 확보했습니다. 데이터 절대량 확보를 위해 크롤링과 더불어 증강 기법을 함께 활용하여 총 52,500건의 리뷰를 수집했습니다.

### 3.2 전처리
- 결측치(Null/빈 리뷰) 제거
- 불필요한 특수문자, 이모지, 반복 자모 등 정제
- 텍스트 정규화를 통한 분석 정확도 확보

### 3.3 탐색적 데이터 분석 (EDA)
EDA 단계에서 다음의 세 가지 핵심 패턴을 확인했습니다.

1. **앱별 리뷰 수 분포**: 앱별로 리뷰량 편차가 존재하여, 특정 앱에 데이터가 편중되지 않도록 분포를 점검했습니다.
2. **별점 분포의 양극화**: 별점은 3점 부근의 중립 평가보다 **1점과 5점으로 뚜렷하게 양극화**되는 경향을 확인했습니다. 이는 만족/불만족이 명확한 극단적 경험을 가진 사용자가 리뷰 작성에 더 적극적임을 시사합니다.
3. **리뷰 길이와 감성의 상관관계**: 부정적 경험이나 구체적인 불만(과금 이슈, 사기 피해 등)을 서술할 때 **리뷰 길이가 길어지는 경향**이 관찰되었습니다. 이는 단순 긍정 리뷰("좋아요", "재밌어요")에 비해 불만 리뷰는 피해 경험을 구체적으로 서술하려는 경향이 크기 때문으로 해석됩니다.

### 3.4 데이터 라벨링
샘플 2,000건에 대해 긍정/부정/중립/관계없음 4개 클래스로 1차 AI 라벨링을 수행한 후, 라벨링 품질 확보를 위해 연구자가 직접 전체 라벨을 검수·보정하는 과정을 거쳤습니다.

### 3.5 모델 학습
- 라벨링이 완료된 데이터를 Train/Test = 8:2 비율로 분할
- 수업 시간에 배포된 **KoELECTRA** 원본 소스코드를 변형 없이 그대로 적용하여 감성 분류 모델을 학습 및 평가
- 별도의 아키텍처 수정 없이 베이스라인 성능을 확인하는 것을 본 단계의 목표로 설정

## 4. 주요 인사이트

1. **불만의 본질은 '기능'이 아니라 '신뢰'다.**
   부정 리뷰의 상당수가 매칭 알고리즘 자체보다 결제 유도 방식, 허위/사기 계정 방치, 오류 대응 미흡에 집중되어 있음을 확인했습니다.

2. **극단적 감성이 리뷰 데이터를 지배한다.**
   별점의 양극화 현상은 감성 분류 모델 설계 시 중립 클래스의 데이터 희소성 문제로 이어질 수 있어, 클래스 불균형에 대한 고려가 필요함을 확인했습니다.

3. **리뷰 길이는 불만의 강도를 나타내는 보조 지표가 될 수 있다.**
   장문 리뷰일수록 부정 감성일 가능성이 높다는 패턴은, 추후 리뷰 길이를 피처로 활용한 추가 분석의 가능성을 시사합니다.

## 5. 결론 및 향후 과제

본 프로젝트는 데이팅 앱 사용자 리뷰 52,500건을 기반으로 감성 분류 파이프라인을 구축하고, 사용자 이탈의 핵심 원인이 '과금 유도', '스캠/허위 계정', '시스템 오류'라는 신뢰 저해 요인에 있음을 데이터로 확인했습니다.

**향후 과제**
- 라벨링 샘플 수 확대(2,000건 → 전체 데이터셋 수준)를 통한 모델 일반화 성능 검증
- 중립/양가감정(Ambivalent) 리뷰에 대한 세분화된 클래스 설계
- 앱별 비교 분석을 통한 서비스별 페인 포인트 차별화 도출
- 신뢰도 저해 요인(스캠, 허위 계정)에 대한 키워드 기반 세부 토픽 모델링 추가
